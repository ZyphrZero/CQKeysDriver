# C# 驱动管理与虚拟 HID 输入测试

这是 Windows x64 / .NET Framework 4.7.2 WPF 示例。测试输入通过本项目 DLL → KMDF/VHF → Windows HID 栈发送，
不使用 `SendInput`、`keybd_event` 或 `mouse_event` 替代驱动。

## 部署与启动

1. 构建 `cqkeysdll/cqkeysdll.vcxproj` 的同配置 x64 DLL（C# Release 对应原生 Release，Debug 对应 Debug）。
2. 将有效签名且相互匹配的 `cqkeys.inf`、`cqkeys.sys`、`cqkeys.cat` 放入本目录的 `dll/`。
3. 构建 `CqKeys.csproj`，配置为 `Release|AnyCPU` 或 `Debug|AnyCPU`；输出实际固定为 x64。
   构建从 `../cqkeysdll/x64/$(Configuration)/cqkeysdll.dll` 显式复制 DLL 到 EXE 同目录，其余包文件放在输出的 `dll/` 子目录。
4. 在隔离的测试系统上以管理员身份运行 `CqKeys.exe`，点击“安装驱动”。只有安装和连接都成功才启用测试按钮。

缺少文件、权限、签名吊销或设备启动失败不会被视为成功。启动错误会显示系统错误以及可用的 PnP Problem Code/NTSTATUS。
若显示 `STATUS_IMAGE_CERT_REVOKED`，须更换符合内核签名要求的完整驱动包；界面测试不能解除签名拦截。

原生 DLL 源文件缺失时构建失败，不会静默沿用输出目录的旧副本；每次构建都复制指定源文件，不按目标时间戳保留旧 DLL。
使用其他已构建 DLL 时必须显式传入 `/p:CqKeysNativeDll=完整路径`；构建日志会显示源路径和目标路径。
`dll/cqkeysdll.dll` 不再作为默认来源，C# 构建本身不会自动构建原生项目或修改驱动包签名。
安装日志记录请求路径、进程实际加载路径及删除接口是否可用；加载路径不符或出现多个同名模块时拒绝驱动操作。
更新磁盘 DLL 不会替换运行中进程的模块，应先完成清理并退出程序，再构建、重新启动。

## 测试输入

保持本窗口在前台、松开 Ctrl/Alt/Shift/Win，不要操作实体键鼠。测试会产生真实系统输入，勿在重要业务操作期间运行。

- **键盘测试（F8）**：发送一次 F8 按下，约 80 ms 后释放；本窗口分别统计收到的 F8 按下与释放事件。
- **鼠标测试（右移/返回）**：发送水平 `+24` 和 `-24` 个 HID 相对计数，中间约 150 ms；不发送点击或滚轮。
  请把指针留在窗口内。Windows 加速、缩放、边界裁剪可能改变屏幕位移，不能保证精确回到起点。
- **取消测试**：请求 DLL 取消并清理。失去窗口激活或运行超过 5 秒也会请求取消。
  5 秒是发起取消的时限，不是驱动必然完成清理的保证；已经提交的输入不能撤回。
- 运行期间禁止再次测试、安装或卸载。关闭窗口会先请求取消，等待测试结束后可再次关闭或卸载。
  测试失败或执行阶段取消后须先卸载清理再重新连接；无法确认结束的任务留给原生生命周期清理，不强行释放。

## 如何判断结果

日志和接收区提供两层证据，不能互相替代：

1. **DLL 执行结果**：核对任务状态、完成动作数、提交序号及输入/清理错误。部分完成、结果不确定、清理失败均不算成功。
2. **本窗口接收事件**：在测试发送期间及结束后短暂观察窗口的 WPF 键盘/鼠标事件；未观察到事件时明确显示“不能确认端到端输入生效”。

接收区不是设备来源鉴定：实体键鼠也可能产生相同事件，鼠标事件可能合并。观察到事件不证明它来自此虚拟设备，
更不证明其他应用已经接收。需要设备级验证时，应另行使用能够关联设备实例的 Raw Input 接收器及隔离验收流程。
本项目是纯软件虚拟 HID，不是实体 USB 硬件，也不承诺与物理设备不可区分或绕过其他应用的输入限制。

## 卸载与 Driver Store

“卸载驱动”默认只移除设备节点，保留 Driver Store 包。测试时可勾选“卸载时删除 Driver Store 包（测试用）”，
点击卸载并确认后，通过新版 DLL 的 `UnloadNTDriverAndPackage` 删除本次暂存及设备绑定的包。
先停止输入、关闭连接、移除设备，之后仅按系统提供的精确 OEM INF 名删除；不会强制删除其他设备使用的包，
也不会清扫所有历史版本。失败保留管理会话和删除选择，供卸载或关闭时重试；需要重启时不自动重启。
仅勾选后关闭窗口不发起新的删除请求。删除接口在记录删除意图和改变输入状态前检查；旧 DLL 缺少接口时
报出实际加载路径，不执行卸载、不锁存删除请求，可取消勾选后显式普通卸载或关闭。已经开始但失败的包删除仍保留重试意图。
重新构建同配置原生 DLL，再构建 C# 即可更新输出副本；本功能不需要更新 SYS。
重新安装仍须提供完整且签名有效的 INF/SYS/CAT，删除 Driver Store 包不能修复签名吊销或绕过系统策略。

## 自动化检查

```powershell
& $msbuild .\tests\csharp_lifecycle_test.csproj /p:Configuration=Release /p:Platform=AnyCPU
.\tests\bin\csharp-lifecycle\Release\csharp_lifecycle_test.exe
```

从仓库根目录运行，`$msbuild` 为 Visual Studio MSBuild 路径。测试覆盖结构布局、固定输入序列、取消、任务/清理错误、
UI 状态、失焦和接收结果表达；使用明确标注的原生/UI 模拟边界，不安装驱动、不发送输入，不能代替真实 HID 验收。
